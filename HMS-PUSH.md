# Huawei Push Kit

This distribution extends the official Gateway; APNs, FCM and WNS remain compatible.
Android HMS clients register `platform: "android"`, `channel_type: "huawei"` and
their HMS token using the existing device/channel APIs. Keep the same device key.

## Server credentials

Set both `PUSHGO_HUAWEI_APP_ID` and `PUSHGO_HUAWEI_APP_SECRET_FILE` before starting
the Gateway. The file contains the **application OAuth client secret** for the
application ID, not the AGC project's client secret. Restrict access to this file;
do not commit it, put its contents on the command line, or include it in an APK.
Existing APNs/FCM/WNS token-service settings remain required by the official server.
If neither Huawei variable is configured, Huawei sends remain retryable until
their existing delivery deadline; existing providers keep working.

## Delivery behavior

- Uses the application OAuth endpoint and cached, single-flight credentials.
- Only business code `80000000` with HTTP success means successful submission.
  The partial-success code is not accepted as success for a single recipient.
- Data-only messages preserve the existing PushGo message/event/thing protocol.
  HMS transport urgency is initially `NORMAL`, as verified on the test handset;
  notification severity stays in the original payload and Android notifications.
- The 4096-byte check counts UTF-8 bytes of the final escaped message excluding
  recipient tokens. Oversized direct messages use the existing cached pull copy
  and small wakeup message. A provider size rejection can also downgrade to pull.
- Every retry recalculates TTL from the persisted absolute deadline. Expired jobs
  are not sent, including jobs that expire while acquiring OAuth access.
- Huawei has its own durable queue and adaptive worker lane. Old FCM jobs and
  frozen submissions remain readable; absent channel type in old Android
  submissions continues to mean FCM. A changed device route fences old jobs.
- App/credential mismatch responses do not delete device routes. Error logs store
  numeric Huawei codes instead of raw responses that may contain recipient tokens.

## Rollout

Deploy the compatible Gateway first, then upgrade the Android client. Keep old
FCM credentials until old clients and jobs are retired. A rollback of Android
requires re-registering its FCM route; never reuse an HMS token as an FCM token.
Do not roll the Gateway back while active Huawei routes/jobs remain.

Local tests use mock HTTP endpoints and test credentials, without real pushes.
The real-device probe establishes Token/OAuth/NORMAL callback delivery only;
production protocol UAT and long-term power-management behavior are separate gates.

Protocol reference: https://developer.huawei.com/consumer/en/doc/hmscore-references/https-send-api-0000001050986197

## Verified on 2026-10-05

The compiled Gateway 1.3.2 ran in local Docker with SQLite persistence. Health,
readiness, authentication rejection, Huawei route registration/removal, Huawei
OAuth and container restart checks passed. A 13-operation batch reached `sent`,
including wakeup/pull and ACK; the user confirmed handset results for all four
severity levels, rich messages, deduplication, things and linked events.
API message `ttl` is an absolute expiration timestamp, not a duration in seconds.
Thing actions require `observed_at`; thing-scoped messages require `occurred_at`;
events require `event_time`. Thing/event operation IDs are generated by Gateway.
Local credentials, database files and compiled runtime binaries are not included.
